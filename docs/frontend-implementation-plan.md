## 0. Исходное состояние

Уже есть: Vite + React 19, TypeScript, alias `@/`, SCSS Modules, React Router, Zustand,
react-dropzone, Vitest, Playwright, Oxlint, React Compiler. Каркас папок (`pages/`,
`features/conversion/`, `api/`, …). Шаблон Vite заменён на SPA-shell (этап A).

**Цель плана:** заменить шаблон на SPA по ТЗ, слой за слоем, с проверяемым результатом на каждом
этапе.

**Зависимость от backend:** UI-контракты (`/api/auth/*`, UI-jobs, download, shares) можно сначала
мокать; интеграция — когда Nest отдаёт те же контракты. Публичный `X-API-Key` в SPA **не** кладём
([architecture.md](./architecture.md) §3.1).

## 4. HTTP-клиент и типы API

**Зачем:** тонкий слой `src/api/` ([architecture.md](./architecture.md) §3.1).

| Шаг | Действие                                                                                       | Критерий готовности                                                    | Статус |
| --- | ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- | ------ |
| 4.1 | Базовый `fetch` с `credentials: 'include'` (cookie JWT)                                        | Cookie уходит на `/api/auth/*` и UI-jobs                               | ⬜     |
| 4.2 | Типы ответов: Job, User, StoredFile, ShareLink, ApiError                                       | Без лишнего `any`                                                      | ⬜     |
| 4.3 | Маппинг `error.code` → русские сообщения ([technical-task.md](./technical-task.md) §5.1, §7.5) | UI никогда не показывает сырой английский `message` как основной текст | ⬜     |
| 4.4 | Обработка 401 (сессия), 429 (rate limit), 5xx (toast)                                          | Единая точка                                                           | ⬜     |
| 4.5 | Мок-адаптер или MSW / ручные stubs до готовности Nest                                          | Home/Auth можно разрабатывать параллельно с API                        | ⬜     |

**Контракты UI (ориентир):**

| Область      | Эндпоинты (ожидаемые)                                            |
| ------------ | ---------------------------------------------------------------- |
| Auth         | `POST /api/auth/register`, `login`, `logout`; `GET /api/auth/me` |
| Jobs (UI)    | `POST` multipart → job; `GET` status; download via signed URL    |
| Account      | профиль, `save_conversions`, API-ключ, files, shares             |
| Public share | метаданные + download по token                                   |

Polling: **каждые 2 с**, пока `queued` \| `processing`; стоп на `completed` / `failed` или таймаут
60 с ([technical-task.md](./technical-task.md) §7.2, §13 #23).

## 5. Auth: сессия, guard, формы входа/регистрации

**Зачем:** ЛК и персональные настройки ([technical-task.md](./technical-task.md) §4.3, §6).

| Шаг | Действие                                                                   | Критерий готовности                     | Статус      |
| --- | -------------------------------------------------------------------------- | --------------------------------------- | ----------- |
| 5.1 | Zustand (или лёгкий auth-store): `user \| null`, `status`                  | Header переключается Войти ↔ ЛК         | 🟡 заглушка |
| 5.2 | `GET /api/auth/me` при старте приложения                                   | Гидратация сессии                       | ⬜          |
| 5.3 | `/login`: email, пароль, «Запомнить меня», ссылки forgot/register          | Чекбокс обязателен (30 суток / session) | 🟡 вёрстка  |
| 5.4 | `/register`: имя, email, пароль + подтверждение; CTA Telegram «позже в ЛК» | Валидация: ≥8, буква + цифра            | 🟡 вёрстка  |
| 5.5 | Ошибки: «Неверный email или пароль»; занятый email + ссылка на login       | Без enumeration по полям на login       | ⬜          |
| 5.6 | После register → автологин → редирект `/account`                           | UC-02                                   | ⬜          |
| 5.7 | Protected route `/account`: редирект `/login?next=...`                     | §5.1 матрица                            | ⬜          |
| 5.8 | Logout                                                                     | Инвалидация + UI guest                  | ⬜          |

**Критерий этапа:** ручной проход register → account → logout → login.

**Зачем:** одна операция = один файл; UI через jobs + polling ([architecture.md](./architecture.md)

| Шаг | Действие                                                                       | Критерий готовности              | Статус |
| --- | ------------------------------------------------------------------------------ | -------------------------------- | ------ |

| 6.2 | Клиентская валидация до upload: 1 файл, ≤10 МБ, расширение под пару, не 0 байт | UC-05; тексты из §5.1            | ⬜     |
| 6.3 | Upload multipart + старт job                                                   | Переход Selected → Uploading     | ⬜     |
| 6.4 | Polling 2 с                                                                    | Processing с индикатором         | ⬜     |
| 6.5 | Success: `download_url`, кнопки Скачать / Поделиться                           | Состояния §5.2                   | ⬜     |
| 6.6 | Failed / timeout / network: RU + Retry                                         | Матрица §5.1                     | ⬜     |

**Направления v1:** JPG→PNG, PNG→JPG, DOCX→PDF, PDF→DOCX. Отдельных URL под типы нет — только
сегмент на главной.
