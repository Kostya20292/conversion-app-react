# Техническое задание: веб-сервис конвертации файлов

**Название продукта:** Convertly  
**Слоган:** конвертация файлов онлайн

**Стек технологий:** [`TECH_STACK.md`](./TECH_STACK.md).

---

## 1. Цель и границы проекта

### 1.1. Цель

Разработать небольшой по объёму веб-сервис **Convertly** для конвертации файлов с:

- удобным UI для разовых и пакетных конвертаций (несколько файлов за одну операцию);
- шарингом результатов по публичной ссылке;
- авторизацией и личным кабинетом;
- публичным API, защищённым API-ключом;
- опциональным сохранением результатов конвертации в профиле пользователя;
- адаптивной вёрсткой под desktop и мобильные браузеры.

### 1.2. Аналоги

| Сервис                                           | Что взять за образец                                         |
| ------------------------------------------------ | ------------------------------------------------------------ |
| [ILovePDF](https://www.ilovepdf.com/word_to_pdf) | Простой сценарий «загрузил → конвертировал → скачал»         |
| [Convertio](https://convertio.co/)               | Dropzone на главной, API для разработчиков, статусы процесса |
| [CloudConvert](https://cloudconvert.com/)        | Документация API, ключи, история задач                       |
| [Smallpdf](https://smallpdf.com/)                | Карточки инструментов, спокойный SaaS-UI                     |

## 2. Форматы конвертации (v1)

### 2.1. Рекомендуемый стартовый набор

| Направление | Вход       | Выход      | Зачем в v1                                   |
| ----------- | ---------- | ---------- | -------------------------------------------- |
| Изображения | JPG / JPEG | PNG        | Лёгкий объём, быстрая обработка, понятный UX |
| Изображения | PNG        | JPG / JPEG | Симметрия формата, минимальные доп. затраты  |
| Документы   | DOCX       | PDF        | Главный «офисный» сценарий (аналог ILovePDF) |
| Документы   | PDF        | DOCX       | Обратное направление к DOCX → PDF            |

### 2.2. Решение по направлению PDF → DOCX

**Решение для v1:** реализовать **DOCX → PDF** и **PDF → DOCX** обязательно.

**Примечание:** качество PDF → DOCX зависит от структуры исходника (сканы, сложная вёрстка). При ошибке конвертации — стандартная обработка из §5.

### 2.3. Ограничения файлов

| Параметр                                       | Значение v1                     | Комментарий                                              |
| ---------------------------------------------- | ------------------------------- | -------------------------------------------------------- |
| Макс. размер одного файла (UI / API)           | 10 МБ                           | Достаточно для JPG/PNG и типичных DOCX                   |
| Число файлов за одну пакетную операцию         | до 20                           | Все файлы одного направления конвертации                 |
| Макс. суммарный объём пакета                   | 50 МБ                           | Защита от перегрузки                                     |
| Таймаут конвертации одного файла               | 60 сек                          | После — ошибка по этому файлу; остальные продолжают      |
| Таймаут всего пакета                           | 10 мин                          | Общий предел фоновой обработки                           |
| Хранение исходников                            | до конца задачи + короткое TTL  | Исходник удаляется после успешной конвертации или по TTL |
| Хранение результатов без «сохранять в профиль» | 24 часа или до скачивания + TTL | Автоочистка                                              |
| Хранение в профиле                             | бессрочно (до ручного удаления) | До ручного удаления пользователем                        |
| TTL публичной ссылки шаринга (по умолчанию)    | 7 суток                         | Можно отозвать раньше из ЛК                              |

### 2.4. MIME / расширения

Сервер валидирует **и расширение, и MIME-тип** (по содержимому / magic bytes, где возможно). Расширение alone недостаточно.

Допустимые соответствия:

| Операция   | Разрешённые расширения | Ожидаемые MIME                                                            |
| ---------- | ---------------------- | ------------------------------------------------------------------------- |
| JPG → PNG  | `.jpg`, `.jpeg`        | `image/jpeg`                                                              |
| PNG → JPG  | `.png`                 | `image/png`                                                               |
| DOCX → PDF | `.docx`                | `application/vnd.openxmlformats-officedocument.wordprocessingml.document` |
| PDF → DOCX | `.pdf`                 | `application/pdf`                                                         |

## 3. Роли и сущности

### 3.1. Роли

| Роль              | Возможности                                                                                            |
| ----------------- | ------------------------------------------------------------------------------------------------------ |
| Гость             | Разовая и пакетная конвертация UI; скачивание; открытие shared-ссылок; просмотр API docs               |
| Пользователь      | Всё как у гостя + ЛК, API-ключ, сохранение файлов, создание/отзыв share-ссылок, редактирование профиля |
| Получатель ссылки | Просмотр/скачивание файла(ов) по публичной ссылке без аккаунта (если ссылка валидна)                   |
| Система           | Фоновые задачи конвертации, TTL-очистка, выдача ключей, истечение share-ссылок                         |

### 3.2. Основные сущности

Ниже — «объекты» данных, которые живут в системе. Это не экраны, а то, что хранится в БД / storage.

#### User (пользователь)

Аккаунт человека после регистрации.

| Поле             | Зачем                                     |
| ---------------- | ----------------------------------------- |
| email / логин    | вход в систему                            |
| password (hash)  | пароль в открытом виде не храним          |
| display name     | имя в ЛК                                  |
| telegram_id      | привязка для восстановления пароля        |
| save_conversions | переключатель «сохранять файлы в профиле» |
| timestamps       | когда создан / обновлён                   |

Связан с: своим **ApiKey**, списком **StoredFile**, своими **ShareLink**.

---

#### ConversionBatch (пакет конвертации)

Одна «операция» на главной или в API: пользователь загрузил **один или несколько** файлов и нажал «Конвертировать».

Даже если файл один — это всё равно batch из одного job (так проще код: один сценарий и для 1, и для 20 файлов).

| Поле              | Зачем                                                                    |
| ----------------- | ------------------------------------------------------------------------ |
| id                | идентификатор пакета                                                     |
| user_id           | кто запустил (`null`, если гость)                                        |
| target_format     | во что конвертируем (png / jpg / pdf / docx)                             |
| status            | общий итог: `queued` → `processing` → `completed` / `partial` / `failed` |
| source_of_request | откуда: `ui` или `api`                                                   |
| timestamps        | когда создан / завершён                                                  |

**Статусы пакета:**

- `completed` — все файлы ок
- `partial` — часть ок, часть с ошибкой
- `failed` — ни один не удался

Внутри пакета лежит несколько **ConversionJob** (по одному на файл).

---

#### ConversionJob (задача на один файл)

Конвертация **конкретного** файла внутри пакета.

| Поле                          | Зачем                                |
| ----------------------------- | ------------------------------------ |
| id                            | идентификатор задачи                 |
| batch_id                      | к какому пакету относится            |
| user_id                       | владелец (может быть `null` у гостя) |
| source_format / target_format | откуда → куда                        |
| status                        | статус именно этого файла            |
| error_code                    | код ошибки, если упал                |
| sizes                         | размер исходника / результата        |
| created_at / finished_at      | таймлайн                             |

Пример: загрузили 5 JPG → PNG → 1 batch + 5 jobs.

---

#### StoredFile (сохранённый файл в профиле)

Результат конвертации, который **лежит в личном кабинете** (если включён `save_conversions`).

| Поле               | Зачем                                                                     |
| ------------------ | ------------------------------------------------------------------------- |
| связь с job / user | чей файл и из какой задачи                                                |
| имя                | как показывать в списке                                                   |
| путь / storage key | где лежит файл (способ хранения — см. [`TECH_STACK.md`](./TECH_STACK.md)) |
| размер             | для UI                                                                    |
| флаг «в ЛК»        | доступен ли в списке профиля                                              |

Если сохранение выключено — результат всё равно можно скачать временно, но **StoredFile** в профиле не создаётся (или создаётся только временный, без показа в ЛК — на усмотрение реализации).

---

#### ShareLink (ссылка «поделиться»)

Публичная ссылка вида `/s/:token`, по которой другой человек скачивает результат **без входа**.

| Поле               | Зачем                                              |
| ------------------ | -------------------------------------------------- |
| token              | секретный кусок URL                                |
| owner_user_id      | кто создал (у гостя может быть без владельца в ЛК) |
| file_id / batch_id | что именно отдаём по ссылке                        |
| expires_at         | когда протухнет (по умолчанию 7 дней)              |
| revoked_at         | если владелец отозвал раньше                       |

В v1 пароля на ссылку **нет** — доступ только по секретному token + TTL + отзыв.

---

#### ApiKey (ключ API)

Ключ из личного кабинета для запросов к API (`X-API-Key`).

| Поле                         | Зачем                                                                              |
| ---------------------------- | ---------------------------------------------------------------------------------- |
| hash ключа + короткий prefix | в БД не храним ключ целиком открытым; prefix вроде `cv_live_ab12…` для отображения |
| user_id                      | чей ключ                                                                           |
| created_at / revoked_at      | когда выдан / перевыпущен (старый отзывается)                                      |

---

#### Как это связано (схема)

```
User
 ├── ApiKey (обычно один активный)
 ├── ConversionBatch ──┬── ConversionJob (файл 1) ──► результат
 │                     ├── ConversionJob (файл 2) ──► результат
 │                     └── …
 ├── StoredFile (если save_conversions = true)
 └── ShareLink ──► указывает на StoredFile или на batch/job
```

Гость тоже создаёт Batch + Job, но без User / StoredFile в профиле; ShareLink у гостя — временный.

#### Блоки

| #   | Блок                           | Описание                                                                               | Сценарии использования                      |
| --- | ------------------------------ | -------------------------------------------------------------------------------------- | ------------------------------------------- |
| 1   | Hero                           | Бренд **Convertly** + подзаголовок («Конвертируйте файлы онлайн и через API»)          | Первый контакт, понимание ценности          |
| 2   | Переключатель типа конвертации | Табы/сегменты: `JPG ↔ PNG`, `DOCX ↔ PDF`                                               | Выбор направления до или после выбора файла |
| 3   | Dropzone                       | Drag-and-drop + кнопка «Выбрать файлы»; подсказка лимитов (до 20 файлов, 10 МБ каждый) | Загрузка одного или пакета файлов           |
| 4   | Список выбранных файлов        | Для каждого: имя, размер, иконка, удалить; кнопка «Очистить всё»                       | Правка пакета перед стартом                 |

| 6   | Прогресс / статус              | Общий прогресс пакета + статус по каждому файлу                                        | Ожидание; частичный успех виден сразу       |
| 7   | Результат                      | Скачать по одному; «Скачать всё (ZIP)» если >1 успеха; кнопка «Поделиться»             | Получение и шаринг                          |

**Авторизованный:** если `save_conversions = true`, успешные файлы появляются в ЛК; share-ссылки можно отозвать из ЛК.

### 4.4. Восстановление доступа (`/forgot-password`, `/reset-password`)

**Способ v1 (по ТЗ):** восстановление через **Telegram** вместо email-писем.

#### Поток

1. Пользователь вводит email/логин на `/forgot-password`.
2. Если у аккаунта **привязан Telegram** — бот отправляет одноразовый код / deep-link на сброс.
3. Пользователь вводит код на сайте или переходит по ссылке → задаёт новый пароль.
4. Если Telegram **не привязан** — сообщение: «Привяжите Telegram в личном кабинете заранее» (без раскрытия, существует ли аккаунт — единый нейтральный ответ для анти-enumeration где возможно).

#### Блоки

| Блок                                | Назначение                                       |
| ----------------------------------- | ------------------------------------------------ |
| Форма запроса кода                  | Старт восстановления                             |
| Инструкция «откройте Telegram-бота» | UX ожидания                                      |
| Поле ввода кода                     | Подтверждение                                    |
| Форма нового пароля                 | Завершение                                       |
| Состояния ошибок                    | Истёкший код, неверный код, Telegram не привязан |

### 4.6. Страница публичного шаринга (`/s/:token`)

Страница для получателя ссылки (без обязательного входа).

| Блок                                  | Описание                                  | Сценарии                   |
| ------------------------------------- | ----------------------------------------- | -------------------------- |
| Метаданные файла/пакета               | Имя, формат, размер, срок действия ссылки | Понимание, что скачивается |
| Скачать / Скачать ZIP                 | Основное действие                         | Получение файла            |
| Состояние «ссылка истекла / отозвана» | Понятный текст без деталей владельца      | Ошибка доступа             |
| CTA «Сконвертировать свой файл»       | Ссылка на главную                         | Привлечение в сервис       |

#### Правила шаринга (обязательные)

1. Создать ссылку можно после успешной конвертации (кнопка «Поделиться») или из ЛК по сохранённому файлу.
2. Ссылка даёт доступ на **скачивание** результата (не исходника), без права редактировать чужой профиль.
3. Владелец может **отозвать** ссылку в любой момент; после отзыва и по истечении TTL — `410` / страница «ссылка недоступна».
4. Гость может создать временную share-ссылку на только что сконвертированный результат (привязка к job/batch, не к профилю).
5. «Совместная работа» в v1 = **шаринг по ссылке** (не real-time co-editing документов).
6. Пароля на ссылку нет.

## 5. Поведение UI при непредвиденных ситуациях

Принцип: **понятное сообщение рядом с зоной действия** + возможность повторить. Без «сырых» stack trace.

### 5.1. Матрица ошибок (UI)

| Ситуация                             | Когда ловим                     | Реакция интерфейса                                                  | Действия пользователя                     |
| ------------------------------------ | ------------------------------- | ------------------------------------------------------------------- | ----------------------------------------- |
| Файл слишком большой (>10 МБ)        | До загрузки / на `change` input | У файла статус error: «Максимальный размер — 10 МБ. Ваш файл: X МБ» | Убрать файл / выбрать другой              |
| Превышен лимит числа файлов (>20)    | При добавлении в пакет          | «За раз можно до 20 файлов»                                         | Убрать лишние                             |
| Превышен суммарный объём пакета      | При добавлении                  | «Суммарный размер пакета — не более 50 МБ»                          | Убрать часть файлов                       |
| Неверное расширение                  | При выборе файла                | «Для JPG → PNG нужен файл .jpg/.jpeg» (по проблемному файлу)        | Заменить файл или сменить тип конвертации |
| MIME не совпадает с расширением      | На сервере после upload         | «Файл повреждён или имеет неверный тип»                             | Заменить файл                             |
| Пустой файл (0 байт)                 | Клиент + сервер                 | «Файл пустой»                                                       | Заменить                                  |
| Часть файлов в пакете с ошибкой      | После обработки                 | Статус пакета `partial`; у успешных — скачать, у ошибок — причина   | Скачать успешные / заменить ошибочные     |
| Сеть оборвалась при upload           | Клиент                          | «Не удалось загрузить. Проверьте соединение» + Retry                | Повторить                                 |
| Ошибка конвертации на сервере        | Ответ job failed                | «Не удалось конвертировать. Файл может быть повреждён» + Retry      | Другой файл / повторить                   |
| Таймаут конвертации файла            | 60+ сек на файл                 | Ошибка по файлу; остальные в пакете продолжают                      | Упростить файл / повторить                |
| Сервер недоступен (5xx)              | Любой запрос                    | Глобальный banner/toast «Сервис временно недоступен»                | Позже                                     |
| Неавторизован на защищённой странице | Guard роутов                    | Редирект на `/login?next=...`                                       | Войти                                     |
| Сессия истекла mid-flow              | 401                             | Модалка «Сессия истекла» → login                                    | Войти снова                               |
| Rate limit (слишком часто)           | 429                             | «Слишком много запросов. Подождите N сек»                           | Подождать                                 |
| Скачивание просроченного файла       | 404/410                         | «Файл больше недоступен (истёк срок хранения)»                      | Сконвертировать заново                    |
| Share-ссылка истекла / отозвана      | Открытие `/s/:token`            | «Ссылка больше недоступна»                                          | Попросить новую ссылку у владельца        |
| Переключатель сохранения выключен    | После успеха                    | Обычное скачивание/шаринг; без записи в ЛК                          | —                                         |
| Перевыпуск API-ключа                 | Подтверждение                   | Modal: «Старый ключ перестанет работать»                            | Подтвердить / отмена                      |

### 5.2. Состояния dropzone / списка файлов

1. **Idle** — приглашение перетащить файлы (один или несколько)
2. **Drag-over** — визуальный акцент границы
3. **Selected** — список файлов с метаданными
4. **Uploading** — прогресс загрузки (по файлу и общий)
5. **Processing** — статусы по каждому файлу в пакете
6. **Success / Partial** — скачать, ZIP, поделиться
7. **Error** — текст + возможность убрать/заменить проблемные файлы

### 5.3. Доступность (минимум)

- Фокус на кнопках и полях, понятные `aria-label` у dropzone и иконок
- Ошибки связаны с полями (`aria-describedby` / `aria-invalid`)
- Клавиатурный доступ к основным действиям

### 6.2. Сценарии и edge cases

| Ситуация                            | Поведение                                                                                     |
| ----------------------------------- | --------------------------------------------------------------------------------------------- |
| Неверный пароль                     | Общее сообщение «Неверный email или пароль» (без уточнения, что именно)                       |
| Email уже занят при регистрации     | «Этот email уже зарегистрирован» + ссылка на вход                                             |
| Слабый пароль                       | Клиентская + серверная валидация (мин. 8 символов, буква + цифра — уточнить при реализации)   |
| Потеря пароля, Telegram привязан    | Код в Telegram → сброс                                                                        |
| Потеря пароля, Telegram не привязан | Нельзя восстановить автоматически; показать, что нужна предварительная привязка Telegram в ЛК |
| Потеря доступа к Telegram           | В v1 без ручной поддержки — только повторная регистрация / новый аккаунт (учебный проект)     |
| Брутфорс логина                     | Rate limit + временная блокировка по IP/email                                                 |
| Истёкший код восстановления         | «Код устарел, запросите новый» (TTL кода ~10–15 мин)                                          |
| Повторный запрос кода               | Cooldown 60 сек между отправками                                                              |
| Выход                               | Инвалидация сессии                                                                            |

### 6.3. Привязка Telegram

В ЛК:

1. Кнопка «Привязать Telegram» → открывает бота с deep-link `start=bind_<token>`.

## 7. Механизм работы API

### 7.1. Базовые принципы

- Базовый URL: `https://<host>/api/v1`
- Все операции конвертации через API требуют **API-ключ**.
- Ключ передаётся в заголовке: **`X-API-Key: <API_KEY>`** (канонический способ).
- Без ключа / с неверным ключом → `401`.
- Файлы, сконвертированные через API, **сохраняются в профиле**, если у пользователя `save_conversions = true`.
- API поддерживает **один файл и пакет** (несколько `file` в multipart).
- API позволяет **создавать и отзывать share-ссылки** на результаты.
- Сообщения об ошибках API (`error.message`) и `error.code` — на **английском**; UI — на русском.

### 7.2. Эндпоинты конвертации (v1) — модель jobs + polling

**Решение:** асинхронные **jobs**. Клиент создаёт задачу, затем опрашивает статус (polling). UI делает то же «под капотом».

```http
POST /api/v1/jobs
Content-Type: multipart/form-data
X-API-Key: <key>

fields:
  file: <binary>          # один или несколько полей file
  target_format: png | jpg | pdf | docx
```

**Ответ на создание (202):**

```json
{
  "batch_id": "batch_01H...",
  "status": "queued"
}
```

```http
GET  /api/v1/jobs/:id      → status: queued | processing | completed | partial | failed
GET  /api/v1/jobs/:id/download
GET  /api/v1/batches/:id/download.zip
```

**Пример статуса completed (один файл):**

```json
{
  "id": "job_01H...",
  "status": "completed",
  "source_format": "docx",
  "target_format": "pdf",
  "download_url": "https://.../api/v1/files/job_01H.../download",
  "expires_at": "2026-08-05T12:00:00Z",
  "saved_to_profile": true
}
```

**Пример статуса пакета (в т.ч. partial):**

```json
{
  "batch_id": "batch_01H...",
  "status": "partial",
  "target_format": "pdf",
  "zip_download_url": "https://.../api/v1/batches/batch_01H.../download.zip",
  "items": [
    {
      "id": "job_01H...",
      "status": "completed",
      "original_name": "a.docx",
      "download_url": "https://.../api/v1/files/job_01H.../download"
    },
    {
      "id": "job_01H2...",
      "status": "failed",
      "original_name": "b.docx",
      "error": { "code": "conversion_failed", "message": "Conversion failed" }
    }
  ],
  "saved_to_profile": true
}
```

### 7.3. Прочие эндпоинты

| Метод  | Путь                      | Назначение                                       | Auth    |
| ------ | ------------------------- | ------------------------------------------------ | ------- |
| GET    | `/api/v1/me`              | Профиль + флаг save_conversions                  | API key |
| GET    | `/api/v1/files`           | Список сохранённых в профиле                     | API key |
| DELETE | `/api/v1/files/:id`       | Удалить файл из профиля                          | API key |
| POST   | `/api/v1/shares`          | Создать share-ссылку на file_id или batch_id     | API key |
| GET    | `/api/v1/shares`          | Список активных ссылок владельца                 | API key |
| DELETE | `/api/v1/shares/:token`   | Отозвать ссылку                                  | API key |
| GET    | `/api/v1/public/s/:token` | Метаданные + download для получателя (без ключа) | —       |

(UI auth endpoints — отдельно: `/api/auth/login` и т.д.; сессия — по [`TECH_STACK.md`](./TECH_STACK.md).)

### 7.4. Валидация запроса API

1. Проверить API-ключ → user
2. Проверить наличие хотя бы одного `file`
3. Проверить число файлов ≤ 20 и суммарный объём ≤ 50 МБ; каждый файл ≤ 10 МБ
4. Определить source format; сверить с `target_format` (допустимая пара)
5. Создать batch + jobs → конвертировать → ответ (в т.ч. `partial`)
6. Если `user.save_conversions` → сохранить успешные `StoredFile`

### 7.5. Коды ошибок API

| HTTP | code                     | Когда                                   |
| ---- | ------------------------ | --------------------------------------- |
| 400  | `invalid_request`        | Нет файла / нет target_format           |
| 400  | `unsupported_conversion` | Пара форматов не поддерживается         |
| 400  | `invalid_file_type`      | MIME/расширение неверны                 |
| 400  | `batch_too_large`        | >20 файлов или >50 МБ суммарно          |
| 413  | `file_too_large`         | Один файл > лимита                      |
| 401  | `unauthorized`           | Нет/неверный ключ                       |
| 404  | `not_found`              | Job/файл/share не найден                |
| 410  | `gone`                   | Срок хранения / share истёк или отозван |
| 422  | `conversion_failed`      | Ошибка движка конвертации               |
| 429  | `rate_limited`           | Превышен лимит запросов                 |
| 500  | `internal_error`         | Непредвиденная ошибка                   |
| 504  | `conversion_timeout`     | Таймаут                                 |

Пример тела ошибки:

```json
{
  "error": {
    "code": "file_too_large",
    "message": "File exceeds the 10 MB limit"
  }
}
```

### 7.6. Rate limiting (предложение v1)

| Канал              | Лимит                    |
| ------------------ | ------------------------ |
| API convert        | 30 запросов / час / ключ |
| UI convert (гость) | 10 / час / IP            |
| UI convert (user)  | 60 / час / user          |
| Login              | 10 / 15 мин / IP         |

Точные числа можно скорректировать при реализации.

### 7.7. Безопасность API и файлов

- Ключ показывается в ЛК один раз полностью; в БД хранить hash + короткий prefix (`cv_live_ab12…`) для идентификации.
- Download URL — либо с короткоживущим signed token, либо только по API-ключу владельца.
- Запрет path traversal, проверка Content-Type.
- Антивирус/сканирование — вне обязательного scope v1, но желательно упомянуть как future work.
- Не логировать тела файлов и полные API-ключи.

### 7.8. Пример `curl`

```bash
# 1) создать задачу
curl -X POST "https://example.com/api/v1/jobs" \
  -H "X-API-Key: cv_live_xxx" \
  -F "file=@document.docx" \
  -F "target_format=pdf"

# 2) опросить статус
curl "https://example.com/api/v1/jobs/batch_01H..." \
  -H "X-API-Key: cv_live_xxx"
```

## 8. Логика сохранения файлов в профиле

| Условие                                    | Результат                                                                                    |
| ------------------------------------------ | -------------------------------------------------------------------------------------------- |
| `save_conversions = true`, конвертация UI  | Успешные файлы в ЛК + доступно скачивание сразу                                              |
| `save_conversions = true`, конвертация API | Успешные файлы в ЛК (`saved_to_profile: true`)                                               |
| `save_conversions = false`                 | Результат доступен временно по download_url / share; в ЛК **не** появляется                  |
| Переключатель выключили                    | Уже сохранённые файлы **остаются**; активные share-ссылки на них не отзываются автоматически |
| Пользователь удалил файл в ЛК              | Удаление из storage + БД; связанные share-ссылки отзываются                                  |
| Гость                                      | Сохранения в профиль нет; временный download и временный share доступны                      |

## 9. Пакетная конвертация и шаринг (сводка требований)

### 9.1. Пакетная конвертация — обязательно

- UI и API принимают **1…20** файлов одного направления за операцию.
- Прогресс и ошибки — **по каждому файлу**; итог пакета: `completed` / `partial` / `failed`.
- При ≥2 успешных результатах — **скачать ZIP**.
- Один файл = частный случай пакета (тот же UX, без усложнения).

### 9.2. Шаринг по ссылке — обязательно

- После конвертации и из ЛК: создать публичную ссылку `/s/:token`.
- Получатель скачивает без регистрации.
- Владелец видит список ссылок и может отозвать.
- Истечение по TTL (по умолчанию 7 дней) или отзыв → страница «ссылка недоступна».
- Пароля на ссылку нет.
- Real-time совместное редактирование документов — **не требуется**; шаринг = доступ на скачивание.

## 12. Пользовательские сценарии (сводка)

### UC-01. Гость конвертирует DOCX → PDF

1. Открывает главную
2. Выбирает DOCX → PDF
3. Перетаскивает `.docx`
4. Жмёт «Конвертировать»
5. Скачивает PDF
6. Видит подсказку войти для API и сохранения

### UC-02. Регистрация и получение API-ключа

1. Регистрация → ЛК
2. Видит уникальный API-ключ, копирует
3. Читает `/api-docs`
4. Делает `curl` с ключом

### UC-03. Сохранение в профиле

1. В ЛК включает «Сохранять файлы»
2. Конвертирует через UI или API
3. Файл появляется в списке
4. Выключает toggle → новые не сохраняются, старые на месте

### UC-04. Восстановление пароля через Telegram

1. Forgot password → email
2. Код в Telegram
3. Новый пароль → вход

### UC-05. Ошибка большого файла

1. Выбирает файл 25 МБ
2. Сразу видит ошибку лимита, конвертация не стартует

### UC-06. Пакетная конвертация

1. Загружает 5 файлов `.jpg` для JPG → PNG
2. Видит список и общий прогресс
3. Один файл падает с ошибкой → статус `partial`
4. Скачивает успешные по одному или ZIP

### UC-07. Шаринг по ссылке

1. После конвертации жмёт «Поделиться» → копирует URL
2. Другой человек открывает `/s/:token` без входа и скачивает
3. Владелец в ЛК отзывает ссылку → получатель видит «ссылка недоступна»
